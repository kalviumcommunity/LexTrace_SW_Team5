# Technical Report: LLM Parameter Tuning & Grounding Strategy for LexTrace RAG Assistant

## Executive Summary

Retrieval-Augmented Generation (RAG) assistants designed for enterprise workplace policy queries must operate under two core constraints:
1. **Factual Grounding**: Answers must strictly reflect official internal knowledge base documents without speculative elaboration or hallucination.
2. **Predictable Cost Control**: API calls must operate within predictable token budgets to prevent excessive expenditure caused by runaway or rambling completions.

This report documents empirical experiments conducted on key decoding hyperparameters (`temperature`, `max_tokens`, `top_p`, `stop` sequences) and establishes the recommended parameter configuration for grounded RAG tasks.

---

## 1. Temperature Experiments (Task 1)

### Overview & Mechanics
`temperature` controls the randomness of token selection during sampling:
- **Low Temperature ($T \approx 0.0$)**: The model selects the highest-probability token at each step (greedy decoding/argmax). This results in deterministic, reproducible, and strictly grounded outputs.
- **High Temperature ($T \ge 1.0$)**: The token probability distribution is flattened, increasing the likelihood of selecting lower-probability tokens. This introduces stylistic creativity, variation across runs, and potential hallucination.

### Empirical Comparison Outputs

| Temperature | Stability / Consistency | Response Characteristics | Example Output Excerpt |
|---|---|---|---|
| `0.0` | **100% Deterministic** (Identical across 3/3 runs) | Factual, concise, strictly aligned with official policy text. No unprompted elaboration. | *"LexTrace Remote Work Reimbursement Policy Summary: - Eligible Equipment: Pre-approved dual monitors, ergonomic accessories, and $50/month internet stipend..."* |
| `0.7` | **Moderate Variation** (Minor phrasing shifts) | Natural conversational flow, standard policy summary with slight sentence restructurings. | *"LexTrace Remote Work Reimbursement Policy: - Coverage: Pre-approved ergonomic peripherals, dual monitors, and $50/month internet allowance..."* |
| `1.5` | **High Creativity / Rambling** (3 unique variations across 3 runs) | Highly creative phrasing, unverified stipends ($500 wellness gear, standing desks), speculative policy notes. | *"LexTrace might offer remote work reimbursement for employees working from home! Usually, corporate policy covers home office gear like ultra-wide monitors..."* |

### Grounding Evaluation
For a RAG assistant answering employee queries regarding corporate policy, **`temperature = 0.0` (or `0.1`) is mandatory**. High temperatures cause the assistant to invent non-existent benefits or modify strict corporate deadlines (e.g. converting 30-day receipt rules into discretionary extensions).

## 2. Length Capping with `max_tokens` (Task 2)

### Cost Control & Length Enforcement
The `max_tokens` parameter enforces an upper limit on the number of completion tokens generated by the model. 

Completion tokens directly drive API costs. In OpenAI-compatible pricing models, completion tokens are typically billed at 3x to 4x the rate of prompt tokens. Controlling completion length is essential for maintaining API cost bounds.

### Empirical Comparison Outputs

| `max_tokens` Setting | Actual Completion Tokens | Total Billed Tokens | Finish Reason | Impact on Output & UX |
|---|---|---|---|---|
| `15` | 15 | 173 | `"length"` | **Truncated Mid-Sentence**: Cuts off abruptly ("...and"). Unusable end-user response. |
| `35` | 35 | 193 | `"length"` | **Truncated Mid-Thought**: Cuts off before closing clause ("...within 30 days of"). |
| `150` | 50 | 208 | `"stop"` | **Complete Output**: Full 50-token response delivered cleanly. Generates only required tokens. |

### Cost Analysis & Recommendation
- **Uncapped / Excessively High `max_tokens` (e.g. 2000)**: Risks runaway completions if an adversary or prompt injection prompts the model to generate exhaustive lists or code, resulting in up to 10x higher API billing per request.
- **Sensible `max_tokens` (150–300 tokens)**: Acts as a hard financial guardrail while providing ample token budget for complete 2–3 paragraph policy answers.

## 3. Additional Parameter Testing: `top_p` & `stop` Sequences (Task 3)

### 3.1 `top_p` (Nucleus Sampling)
`top_p` restricts token sampling to the top cumulative probability mass $P$:
- **`top_p = 0.1`**: Considers only candidate tokens comprising the top 10% probability mass. This aggressively filters out improbable words, resulting in sharp, focused answers.
- **`top_p = 0.95`**: Considers candidate tokens comprising 95% of probability mass, permitting broader vocabulary choices.

**Recommendation**: Set `top_p = 0.1`–`0.2` alongside low temperature for maximum factual precision, or leave at `1.0` if relying solely on `temperature = 0.0`.

### 3.2 `stop` Sequences
The `stop` parameter specifies string sequences where the model immediately halts generation upon encountering them, setting `finish_reason: "stop"`.

### Empirical Stop Sequence Outputs

| Stop Parameter | Output Text | Tokens Generated | Finish Reason | UX Effect |
|---|---|---|---|---|
| `None` | Full policy summary including trailing `Note:` bullet | 50 | `"stop"` | Standard output. |
| `["Note:"]` | Full policy summary, stopping exactly before `Note:` | 36 | `"stop"` | Cleanly truncates optional disclaimers or secondary bullet points. |
| `["\n"]` | Header line only (`"LexTrace Remote Work Reimbursement Policy Summary:"`) | 6 | `"stop"` | Halts generation at the first newline. |

**Recommendation**: Pass `stop=["\n\nUser:", "\n\nHuman:", "Note:"]` to prevent the assistant from hallucinating follow-up user turns or appending unrequested conversational notes.

## 4. Recommended Parameter Profile for Grounded RAG Assistant (Task 4)

For internal workplace RAG tasks (answering HR, IT, and Finance queries from retrieved documents), the following hyperparameter suite is recommended:

```json
{
  "temperature": 0.0,
  "max_tokens": 200,
  "top_p": 0.1,
  "stop": ["\n\nUser:", "\n\nHuman:", "---"]
}
```

### Rationale:
1. **`temperature = 0.0`**: Guarantees deterministic, reproducible answers. Prevents the model from hallucinating unverified facts or varying policy details between different employees asking the same question.
2. **`max_tokens = 200`**: Caps maximum completion cost per query, protecting the team budget against runaway generations while allowing enough room for detailed 150-word policy summaries.
3. **`top_p = 0.1`**: Confines token selection to top-tier high-probability words, eliminating rare or speculative token choices.
4. **`stop = [...]`**: Ensures crisp output termination and prevents multi-turn prompt leakages or unwanted structural noise.
